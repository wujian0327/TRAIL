## 实现

- `--deterministic` 使用单线程 Tokio actor 和暂停的逻辑时钟。
  模拟时间在 actor 空闲时推进；机器计算速度不再决定消息延迟及 epoch 边界。
- 交易与区块时间戳来自逻辑时钟；genesis 钱包由固定 seed 派生。
  交易额外包含已签名的发起者本地 `simulation_nonce`，使同一秒内相同收付款方的
  多笔交易具有不同身份。旧交易缺少该可选字段时保持原序列化和验证兼容。
- 固定 BA 节点与边插入顺序、运行时邻居顺序、actor 启动顺序、验证者顺序、
  控制消息和余额通知顺序，以及浮点归一化的求和顺序。
- 内存池依次按手续费、生成时间、发起者、交易序号和 hash 排序。
  使用发起者和序号作为 hash 前的平局规则，避免单纯改变 fee 就改变平局交易的优先级。
- 逻辑时间模式关闭周期性的调试区块链转储，使用同步指标写入，避免外部 I/O 完成时间
  改变 actor 调度。指标、交易生成和纳入记录仍完整保存。

该模式目前支持 PoS 和 TRAIL（包括 Fee-only、Ersoy）。它要求非零 wallet seed，
与 `--real-time` 互斥。协议公式、手续费分配、转发成本、探索率、EMA 参数及
`ema_premiums_v2` 行为估计器均保持原设置。逻辑时间模式用于协议模拟，
不提供操作系统网络或真实执行耗时的性能证据。

## 验收流程

入口：`python3 experiments/run_participation_validation.py --max-parallel 3`。
入口冻结二进制及来源，随后依次执行以下阶段；任一阶段失败就停止后续阶段。

1. 小规模单节点干预测试：8 节点、两种机制，核对干预前历史和其他节点的策略。
2. 完整 100 节点短程重复及前缀测试。
3. Fee-only、seed203/209、F=0.005/0.01：每个单元运行 200、200、500 epochs。
   逐项核对所有 CSV 中的策略、收益、工作量、交易、区块和延迟记录；比较不使用浮点容差。
   对 PoS、Ersoy、Full 另做短程重复检查。
4. 重复性通过后，执行完整 100 节点的单节点收益诊断。

每次运行还核对与原输入相同的经济参数、初始 stake、策略、成本、度数和物理拓扑。
相同总时长的运行须匹配原提交负载的指纹。行为估计器的 EMA 从日志独立复算。
诊断阶段不将新运行与旧数值混合作图。

## 单节点收益诊断

`--relay-replay-file` 读取实验用 JSON 策略表，并将内容嵌入 `run_config.json`。
在共同历史之后，其他节点逐次采用基准运行记录的策略；被检查节点分别被固定为 Active
和 Lazy。消息传播、纳入、奖励和 proposer 选择继续由协议实际运行产生。
日志通过 `decision_mode=baseline_replay_intervention` 明确标记该阶段。

首轮诊断使用 seed209、F=0.01，分别检查 Fee-only 与 Full。节点预先按初始最大度数和
最高经济 stake 选择，重合时去重。起点取 epoch9–99 中首个有效负收益决策之后；
不存在该决策时从 epoch25 开始。观察 40 epochs，覆盖贡献评分的两轮激活延迟。
这是少量指定节点的诊断，不作为总体样本或均衡证据。

程序核对两种策略在干预前的节点记录完全一致、其他节点的策略准确重放、stake/成本/度数
保持一致，以及发起交易支出在两种策略间相同。输出包括：

- 多转发获得的中继奖励，以及增加的转发次数和决策成本。
- 根据 epoch 开始时已生效权重计算的额外预期基础出块补贴。
- 实际 proposer 收益，以及采用已实现 proposer 奖励池构造的预期总 proposer 收益代理。
- 上述不同收益口径扣除额外转发成本后的差值，并保留干预前的公共收益信号。

epoch-end 权重用于下一 epoch，因此计算预期出块收益时使用 e-1 的权重。
总 proposer 收益代理中的手续费仍依赖实际 proposer 和传播路径，不能当作精确的
反事实期望收益；有限窗口之外的持续贡献收益也没有测量。实际收益受所选随机轨迹影响。
这些结果用于判断公共组别信号是否适合指导个体，尚不自动替换生产估计器。
